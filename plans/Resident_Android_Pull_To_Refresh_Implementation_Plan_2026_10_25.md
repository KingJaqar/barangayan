## 4. Design

### 4.1 One new file, `components/pull-refresh.tsx` (three exports)

1. **`PullRefreshControl`**: themed `RefreshControl` element for a scroller's `refreshControl` prop (works for `ScrollView` and `FlatList`, F1). Android: spinner `resident.accentText`, circle `resident.card` (F16). Wraps nothing.
2. **`usePullRefresh(handlers?)`** → `{ refreshing, onRefresh, register }`. `onRefresh` is stable; the latest `handlers` live in a ref updated by an effect, so a new array identity never re-registers or re-runs anything. Single flight. Runs owner and registered handlers in parallel with `Promise.allSettled` (a handler returning nothing counts as done; rejections never reach the gesture). `refreshing` ends when all settle or after `PULL_REFRESH_CEILING_MS = 20000`; timer cleared on settle and unmount; no state set after unmount.
3. **`PullRefreshScope` + `useRegisterPullRefresh(handler)`**: context carrying `register`; a data-owning child registers once on mount (latest handler via ref) and unregisters on unmount, so the mounted tab/segment decides what refreshes.

Excluded: toasts, retry logic, caching, minimum spinner time, config objects, global provider. React Compiler is on (F15): refs are touched only in effects and handlers.

### 4.2 Making handlers awaitable

| Source | Change |
| --- | --- |
| `useProfile().refetch` (F3) | Return the `invalidate()` promise (resolved when signed out); widen type in `ProfileData` and the context default. Assignable wherever `() => void` is expected; a scoped search found no consumer that returns it from an effect (F22). |
| `use-emergency-guidelines`, `-hotlines`, `-qr-content`, `-announcements` (F13) | Return the existing chained promise; widen `refetch` type. Their consumers already show a placeholder only when empty (F11), so no silent mode. |
| `useAnnouncements` (F4) | Separate awaitable `refresh`: the effect assigns a function to a ref that re-runs `load()` under the **current key**; failure does nothing; cleanup clears the ref. `retry` unchanged. |
| Home, `DocumentsList`, `RequestTrackingScreen` (F8, F9) | Each effect assigns a pull function to a ref (success identical to its load; failure leaves state unchanged; counters/keys never bumped). |
| Reports, Health, Requests, Logs, Payment, Family members/attendance (F2, F5, F6, F10, F12) | Existing promise-returning functions used as is. |

### 4.3 Failed-pull policy, loop rules

- Sources that already keep content and show their own error (all `RefreshResource` screens, Emergency Info banners) keep doing so. Where today's loader would replace content with an empty/error view (Announcements, Home, Documents, tracking), the **pull** function does nothing on failure: the screen is unchanged and the spinner ends. Mount, retry and realtime loads keep current behavior. Payment keeps its own `refresh()` behavior.
- Never add a positional parameter to a function also used as an `onPress` or realtime callback (F14).
- No pull state is set in render or effects; effects exposing a pull function do not list it as a dependency and never resubscribe channels; no hardcoded colors; no new `entering`/`exiting`/`layout` props.

## 5. Central workflow, environments, shared rules

**Workflow (whole execution, one pass; phases add only the checklist):** Git baseline → ripgrep discovery → Reader validation → scoped Repomix → Reader XML analysis → original-source verification. Repository instructions (`AGENTS.md` is 0 bytes) and user requirements take precedence over tool output.

| Step | Do | Record |
| --- | --- | --- |
| 1 Git | `git rev-parse HEAD`, `git status --short`, diff stat for the touch list; snapshot patch + touch-list copies to `tmp/resident-pull-refresh-20261025/before`; keep `.env`/secrets out. Other sessions' modified files are not ours. | HEAD, counts, snapshot path |
| 2 ripgrep | Narrow path/symbol searches for callers, consumers, tests; batched, bounded output. Repowise is **not installed** (F17) and is not used. | files/callers |
| 3 Reader | Recompute manifest sha256; unchanged keeps findings, changed invalidates dependent `F#` and queues a re-read. Hash match proves identity, not analysis completeness. "Reader" = bounded `Read` with ranges recorded. | hash diff |
| 4 Repomix | Only for files not covered by verified findings: cached `repomix` 1.18.1, `--style xml --compress --stdin`, security checks on; one packet plus small supplements. | selectors, packet hash, omissions |
| 5 Reader XML | Chunks ≤ 12,000 characters or 200 lines; record counts and continuation boundaries; read each required entry fully; reuse only entries with unchanged hash and dependencies. | ranges, findings |
| 6 Source | Open regions compression omitted; run the phase's baseline checks **once** before editing; smallest complete change; review owned diff; verify each gate; rerun only affected checks; keep full outputs instead of rerunning. | results, pre-existing failures |

The context index is edited in place (update a changed fact, never append narrative). Packet size is never reported as usage savings.

**Environments.** MuMuPlayer (API 32, 1080×1920, 480 dpi) is the main Android device, identified by model/API/`wm size` each session and recorded with build, theme, accent, font scale; confirm the loaded bundle matches the working tree. **Docker** runs a disposable isolated backend (DB clone + isolated GoTrue/PostgREST + proxy, the earlier pattern) for C3 and C4; a separate Metro points `EXPO_PUBLIC_SUPABASE_*` at it; failure is made by stopping the proxy container, never by changing device networking. **Brave** is used only as the Chromium for the existing harness tests (D8); no web app is changed. Safety rules carried from earlier device work: no writes to production data (dev builds may be signed in to a production-linked test account: read-only gestures only); never tap Logout, Delete account or Download my data; no Wi-Fi/mobile data/airplane toggling on shared emulators; no Metro web target; no `input text` without a focused field; leave the owner's other apps alone.

**Recovery (all phases).** No phase writes data, schema, config or dependencies, so there is nothing irreversible. Code recovery = restore the phase's snapshot files or revert its owned diff. The isolated Docker stack is disposable: recovery = remove its containers, volumes and the proxy. Device accounts are read-only, so there is no data to restore.

**Per-phase checklist (carried by every phase).** Scope · prerequisites + unchanged hashes · context inputs (`F#`) and regions still to read · baseline checks once before edit · gates · owned-diff review · dead-code sweep (`ripgrep` each removed symbol across `src` and `tests`; no debug or commented-out code) · affected checks rerun.
