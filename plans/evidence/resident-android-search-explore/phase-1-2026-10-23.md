## Transition contract and dependent-phase impact

| Action | Contract |
| --- | --- |
| Header opens entry | Preserve draft, clear submission, capture allowlisted origin, navigate `/search` once |
| Draft edit | Update draft only; submitted snapshot unchanged |
| Valid `submitSearch(input)` from entry | Existing normalization, captured query/origin, one `/explore` transition; returns true |
| Invalid/duplicate pending action | No navigation/persistence; submission returns false |
| `editSearch()` / header Back from submitted Explore | Restore submitted draft and pop to entry, removing Explore history item |
| Header Back from entry | Preserve draft, clear submission, pop to origin; missing session origin falls back Home |
| Direct Explore without submission | Replace with entry; entry Back falls back Home |
| Account/barangay change | Clear transient draft/submission/origin before descendants commit; existing query identity and abort cleanup reject stale work |

One transition per scope/path is accepted until the destination commits. The ref is an event guard; the conditional scope reset updates only the currently rendering component. No new timer/network subscription. Account history serialization, auth filters, request limits and old draft/history APIs remain intact.

Phase 2 must wire keyboard/button/recent/suggestion submissions to this explicit API and persistence contract. Existing keyboard/suggestion behavior is intentionally preserved in Phase 1.
