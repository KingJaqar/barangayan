## Decisions

- **P15-D01 — household QR is generated on the device (T05, G15, PR-11).** `generate-household-qr` sends the profile UUID to `api.qrserver.com`. The code only encodes `{ "type": "household", "profileId": <id> }`, so iOS draws it locally from the signed-in account's own id (and only when the loaded profile is the same account). No identifier leaves the device, no processor disclosure is needed, and there is **no cache** to isolate between accounts. The Edge Function is unchanged and still serves Android and web. This is a "qualified local equivalent" in G15's words; the owner approved it in OD-12.
- **P15-D02 — gates.** `evacuationCheckin` (G01, G08, G17, G19) and `householdQr` (G03, G15, G17) were built closed and are **open since OD-12** (non-device, non-live scope; G03, G01, G17, G19 not thereby satisfied; `householdEditing` stays closed). With a gate closed, Scan QR is disabled with an explanation and the household card shows a labelled placeholder (kept and tested). Show QR is not behind a gate (public tenant data; nothing is sent).
- **P15-D03 — only the server's receipt is attendance.** A scan is validated locally (size, JSON, schema, household code, barangay) and then sent once; duplicate camera frames are ignored; a reply that does not arrive is reconciled by reading the resident's own stored rows and is otherwise `unconfirmed` ("not counted as attendance yet"), kept in memory only. Trying again is safe because the RPC returns the first check-in for ten minutes. Closing the scanner while a request is open is disabled; if the screen goes away anyway the attempt becomes `unconfirmed`, never a success.
- **P15-D04 — client does not pre-check the center list.** The RPC is authoritative for "actual active center in the caller's barangay" (P0010/P0011/P0012); a stale cached list could only produce a false refusal.
- **P15-D05 — center QR text.** Same schema and layout as Android (`EVACUATION_CENTER_CHECKIN`, `1.0`, center id, name, barangay id) without `generated_at` (optional in the schema), so the same center always produces the same picture. The share sheet carries the text with Android's title line.
- **P15-D06 — household guidance corrected (T06).** The repository has no staff-side scanner for the household code; staff mark household attendance in the admin Households & Residents records. The card says the code identifies the household for staff, that scanning it in the app does not check the family in, and that staff mark attendance. Android's "quick family check-in" wording is not ported.
- **P15-D07 — no bulk household update (A25-023/024).** Android updates every `household_members.is_checked_in` after a check-in and warns when that fails. iOS never writes household attendance; the confirmation says it records the resident only.
- **P15-D08 — scanner is a modal, not a route.** No route or typed-route change; the Close button is disabled only while a request is open.
- **P15-D09 — guide fallback is written for this app.** Android's seed says presence is "automatically recorded"; the iOS built-in guide says a check-in counts only when the app says it was confirmed, and is shown only when nothing is published or loadable.
