## Delivered behavior and decisions

The existing scoped hook owns the account state; no second attendance hook, polling, realtime channel, persistent operation storage, dependency or migration was added. Optional attendance is one set RPC alongside the roster read. Roster JSON remains separate from parsed display data. Each open editor freezes its expected snapshot, including across focus refresh; a conflict rereads once and requires explicit Save with the retained draft. Successful arrays are validated against requested IDs and normalized fields; null/missing data cannot report success. A pending added UUID survives uncertainty and a confirmed reconciliation does not add it twice. Validation failures retain same-account verified data and pause unsafe editing.

Holder is represented separately from dependents, included in totals and excluded from dependent editing. Server UTC timestamps render in Asia/Manila. Status is never inferred from the editable booleans. Family QR uses installed Canvas, 4-module quiet margin and fixed black/white contrast, with no names/contact/token in its payload. QR/account requests revalidate resident identity. Private client fetches explicitly use no-store; the guest-accessible Family route is explicitly dynamic. Auth changes, cleanup and restored navigation invalidate old data/dialogs before revalidation. Existing theme variables and account font are respected; high-contrast attendance text uses the foreground token.

The existing admin deadline implementation moved byte-for-byte to the shared package and is re-exported by the original admin helper. Six existing admin attendance cases, admin typecheck/lint and three deadline cases verify this integration. No admin workflow redesign or backend authority change.
