The small HistoryResource composes the existing RefreshResource rather than replacing its deadline, abort, deduplication or invalidation semantics. Refresh atomically replaces the already-loaded prefix; it does not discard loaded content/scroll position while fetching. A page failure retains rows and exposes retry. Realtime/reconnect invalidations for Requests/Reports cancel obsolete work and refresh the prefix, rather than appending a conflicting window. Activity retains its existing focus-owned freshness contract. Account/filter keys replace private state immediately; late old results cannot publish. Returning after mutation refreshes only current inputs. A repeated cursor fails visibly rather than looping. Each explicit load adds one page; a full final page can require one empty read to discover the end. Refreshing a deeply loaded prefix may require multiple sequential bounded reads, subject to the existing 30-second deadline; on failure the old window remains with retry guidance.

These are Windows Node v24 host results, not Hermes, actual resident responses or native frame times.
