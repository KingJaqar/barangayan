# Admin Web (`apps/admin-web`) UI Inventory — 2026-10-24

Derived from source only (routes, components, state branches). No screenshots taken, no code changed.
All source paths are relative to `apps/admin-web/src/` unless stated. `(admin)` = `app/(admin)`.

## 0. How to read this

**Single admin role.** Every `(admin)` route is gated by `profiles.role === 'admin'` and `deleted_at IS NULL` (`app/(admin)/layout.tsx`; most pages re-check and `redirect('/login')`). There is **no per-role UI branching** (no super-admin / read-only / clerk variants). The Staff screen's `official_role` values (captain, kagawad, secretary, …) are display and filter data only. They do not change which screens or buttons an admin sees. The only role-like variants are:

- **Admin vs. non-admin** — non-admin sessions are redirected to `/login`; residents go to `/resident`.
- **Own staff record** — in the Staff table, Archive and Delete are disabled for the row whose `profile_id` is the signed-in admin ("You cannot archive/delete your own staff record"), and Edit is disabled in the record sheet (`record-workspace.tsx`).
- **Profile feature gates** — server env flags `ADMIN_PROFILE_ENABLED`, `ADMIN_PROFILE_AUTH_VERIFIED`, `ADMIN_PROFILE_ORIGIN` (`lib/admin-profile/server.ts`).

## 11. Coverage notes

**Could not confirm from code / not present**
- **No role matrix.** Despite the Staff screen's `official_role`, nothing in `apps/admin-web/src` varies by it. Server-side RLS may still deny some actions for some admins. Those appear as error toasts or alerts ("You do not have permission for this action…", `mutateAdminRecord`). The exact deny cases need a second admin account to see them.
- **No bulk selection, no export (CSV / PDF), no breadcrumbs, no global banner, no custom 404, no root error boundary** — none of these exist in the code.
- **Exact lists in `packages/shared`** were not enumerated (accent colours, font options, `OFFICIAL_ROLES`, `ID_TYPES`, waste types, announcement categories, hub icon names, household roles, `NAV` icons). Their visible labels need a read of the shared package.
- **Dashboard and other server components** use Suspense; the dashboard's skeleton → content transition is brief and only visible with throttling.
- **Unread template text** — the per-module `displayLabel` strings for notifications (`lib/audit-notifications.ts`) were not enumerated. Many audit action × entity combinations exist.
- **Header-level**: `NotificationIcon` per-module icons not enumerated.
- **Per-field validation messages** for each content form (zod schemas in `@barangayan/shared`) were not enumerated.

**Backend / environment-dependent states that are hard to reproduce**
- Profile gates: `ADMIN_PROFILE_ENABLED`, `ADMIN_PROFILE_AUTH_VERIFIED`, `ADMIN_PROFILE_ORIGIN` (the "awaiting verification" screens and disabled credential forms), MFA `aal2` challenge, `admin_profile_access` 42501 → redirect, linked-resident `unavailable` / `error` states, password-notice cookie values, email-confirmation callback outcomes, and the proof popup (needs `window.opener`, a 5-minute expiry, and cleanup-failure paths).
- Request **contract v2** rows (SLA `paused` / `running`, fee assessment `pickup_due`, "Previous timing model" and "Previous catalog format" tags) need seeded v1 and v2 data; v1 rows show the older button set.
- **Refund** states depend on PayMongo / QR PH payments and webhook transitions (`pending`, `processing`, `failed`, `refunded`, claim link).
- **Realtime** table refresh (Requests) and notification updates are Supabase Realtime events.
- **Evacuation routing**: needs a `routing_areas` row, a registered graph version, and a bundled routing pack (`lib/routing-packs.ts`) matching the active graph, for "Map ready to edit" vs. "Map preview"; graph load errors; stale snapshot shapes.
- **Incident map**: boundary polygon presence (no boundary → no dashed outline), OSM tile load or failure, cluster zoom behaviour; popups only after clicking a marker. Full-screen is browser-gated.
- **Camera / QR scanning** requires a camera and permission (denied / timeout / unsupported variants).
- **Network-failure variants** (the many "could not be confirmed" warnings, the 15 s load timeouts in the record sheet and ID review, `AbortSignal` timeouts on server loads) need fault injection.
- **Auth/session variants**: expired session mid-use (search "Sign in", households "Reload the page", profile "Sign in again").
- **Data volume**: pagination beyond page 1, the 99+ notification badge, the max-3 toast stack, the 10-colour custom accent limit, and the capacity-full state all depend on data or repeated actions.
- **Stale artifacts**: `apps/admin-web` contains `.next-family-phase2-baseline/` and similar build output, which was ignored. `app/resident/*` is only reachable with a resident account.

**Method**: all routes were enumerated from `src/app/**/page.tsx|layout.tsx|loading.tsx|error.tsx|not-found.tsx|route.ts` and `src/proxy.ts`. Component state branches were read from the files cited above. Some large files (`routing-conditions-editor.tsx`, `editable-data-table.tsx`, `transactions-table.tsx`, `about-us-form.tsx`) were sampled by structure and user-visible strings and not read line by line.
