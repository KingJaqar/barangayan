# Resident Android app (`apps/resident-android-mobile`) — UI inventory

Source-derived inventory of every distinct visual state someone could screenshot. Built by reading the code under `apps/resident-android-mobile/src` (expo-router routes, components, hooks) and the shared helpers it imports from `packages/shared`. Nothing was run, no screenshots were taken, no code was changed.

**Path convention.** `src/` = `apps/resident-android-mobile/src/`. Route files live in `src/app/`; components in `src/components/`.
**Stack.** Expo SDK 57, expo-router (typed routes), React Native 0.86, Reanimated 4, Leaflet-in-WebView maps (`components/map-view.tsx`). Portrait only (`app.json` `orientation: "portrait"`). Package `com.barangayan.resident`.

## 18. Coverage notes

**Not reachable through normal UI (deep link / stale code only):** `/(auth)/welcome`, `/(auth)/value-prop`, `/(auth)/personalization` (nothing navigates into them — `app/index.tsx` goes straight to `auth-choice`), `/(auth)/completion` (documented dead), `/maps/hotline-directory`, `/maps/preparedness-guide` (placeholders, no inbound link), `/home/emergency-info/scan` (no inbound link), `/index/emergency-info/qr-guide` (duplicate stub), `/home/emergency-info/qr-guide` (redirect only). Capture these only via `adb shell am start -a android.intent.action.VIEW -d "barangayan:///…"` style deep links. Unknown-path screen is Expo Router's default (no `+not-found.tsx`).

**Could not confirm from code alone:**
- Exact copy of strings that live in `packages/shared` (e.g., `loginErrorMessage`, `residentSetupFailure`, `residentServiceError`, `accountSettingsRows`, `passwordMode`, `deletionConfirmation`, `FAQ_CATEGORY_META`, `DRIVE_TYPE_CONFIG` labels/colours, `AGENCY_SLA_LABEL`, `homeGreeting`, `RESIDENT_STATUS_LABEL`) — I listed the variants but not every literal.
- Data-dependent content: catalog documents, charter text, FAQ articles, About/Terms content, guidelines, hotlines, QR instructions, alerts, drives — all come from Supabase tables; visible rows depend on seeded barangay data. Admin-managed text (markdown) can contain headings/tables/code that change the layout.
- Whether Android edge-to-edge/predictive-back changes bottom spacing on a given device (`predictiveBackGestureEnabled: false`; behaviour of navigation bars is device/OS dependent).
- `Platform.OS === 'web'` branches exist (e.g., `confirmAction` uses `window.confirm`, Save-QR "Not Supported") but are not part of the Android app.
- Visual appearance of Leaflet map contents (tiles, labels) depends on network and the OSM server; pack basemap requires the installed routing pack (`useOfflineRouting`).

**Conditions that are hard to reproduce on an emulator:**
- Push notifications (needs a physical device + dev build + permission; `Device.isDevice` guard; Expo Go returns early). Local-notification pop-ups from realtime events require another actor to change DB rows.
- Camera: QR scanner and ID camera need an emulator virtual camera; scanning a valid center QR needs a matching `barangay_id`.
- GPS states (stale / inaccurate / approximate / services-off / timeout / blocked) need mock-location control and OS settings toggles; Android 12+ approximate-location prompt varies by API level.
- QR PH payments: states `pending → paid/expired/cancelled/already_paid` depend on PayMongo webhooks/polling (`check-payment-status`, `cancel-payment` edge functions); `PAYMENT_SETTLEMENT_READY` flag gates the QR PH option copy.
- Agency SLA clock (running, paused "waiting for resident", near-target, overdue, completed-beyond) depends on server RPC `service_request_sla_tracking` snapshots and a live ticking clock; legacy "Previous timing model" requests need old rows.
- Staff-driven transitions: request status (submitted → in progress → ready for pickup → completed/cancelled), incident status (open/in-progress/resolved/withdrawn/unresolved), drive-registration status, ID verification (pending → verified/failed/repair-required), family attendance (check-in/out). All need an admin-web action or SQL.
- Account-setup edge cases (`conflict`, `uncertain`, `status_error`, `manage_password`, Google reauth freshness 5-minute window, native callback cold-start hand-off) need crafted auth state or killing the process mid-flow.
- Time-based UI: 24-hour withdraw window, QR expiry countdown, 45/60-second resend cooldowns, 10-s tooltip fade, 12-s "taking longer" copy, greeting by hour, "x minutes ago" stamps.
- Offline-first behaviours (cached DRRM content, offline routing pack, "Showing saved evacuation centers") need airplane-mode toggling; see memory note that airplane mode kills adb on some emulators.
- Share sheet, media-library gallery save and OS permission dialogs are drawn by Android, not the app — appearance differs by OS version/vendor.
- Splash: native splash (1.1) is OS-drawn and very brief; Android 12+ system splash uses the launcher icon treatment.
- Reduced-motion-specific transitions (sheet fades) require the Android "Remove animations" setting; the `useResidentReducedMotion` hook is the source of truth.
- Orientation: portrait is locked, so landscape captures are not applicable; foldable/tablet unfolded widths aren't exercised beyond `MaxContentWidth` clamps.
