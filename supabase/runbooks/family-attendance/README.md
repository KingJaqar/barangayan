## Failure and recovery

1. Stop staff confirmation and have an authorized operator pause mutations; drain existing operations. Staff message: **Attendance recording is temporarily unavailable. Keep the original confirmation details and ask staff to retry when service returns. Do not assume a timeout rolled back a confirmation.** Preserve the pending request/payload for explicit retry while the same authorized dialog remains open; never replay a write on reload/login.
2. Preserve every stay and retry receipt, including closed visits. Capture backup identity, counts, grants and function/view definitions. Repair forward or restore the operator's verified full backup to an isolated target first. Compare all stored fields, actor references, timestamps, receipt results and permissions. Do not drop attendance, prune receipts, delete visits, replay 0139 or fall back to legacy blanket status writes.
3. If web clients are rolled back, keep the server attendance/legacy-write boundary enforced. Additive schema can remain; verify restored/older clients display a clear failure and cannot misreport an old scan as confirmed family presence. Verify no old export/deletion path violates the retained schema.
4. Prove delayed arrival/departure requests return the original receipts while a later visit stays open. Confirm current attendance through an authorized read, never by projecting a replayed receipt. Verify residents still see their own records and other tenants cannot access them. Resume only after target acceptance and explicit operator authorization.
